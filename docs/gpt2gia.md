# GPT2Gia 集成

侧栏选择 **GPT2Gia**，上传或粘贴模型 JSON，选择普通实体或装饰物包装，点击“生成 GIA”。
可下载 GIA、转换摘要与归一化 JSON。该功能只处理现有 JSON，不调用外部 AI 服务。

支持的输入：

- 名称字典：`{"Cube":{"position":[0,0.5,0],"scale":[1,1,1],"color":"#66aaff"}}`。
- 对象列表：每个对象有 `template_id` 时使用该 ID；没有该字段时使用页面默认基础体的 ID。名称字典与 components 格式同样适用，`type` / `type_id` 不覆盖该规则。显式 ID 无效时报告错误，不静默替换为默认值。
- 场景结构：`{"components":[{"id":"cube","position":[0,0.5,0],"scale":[1,1,1]}]}`。字符串 `id` 保留为来源标识，不充当实体数字 ID。

坐标格式为 **Y-UP（Y 轴向上，X/Z 为水平轴）**，向量按 `[x,y,z]` 顺序填写。

材质文件格式为 `{"Cube":{"color":"#ff0000"}}`，按物体名称覆盖颜色。
位置、缩放为三维数组，旋转采用原项目的角度与 Rz × Ry × Rx 约定。`pos`、`rot`、`rgb` 别名也可使用。
颜色还支持 `[r,g,b]`、`[r,g,b,透明度百分比]` 和原导出器的颜色字典格式。

## 独立父级配置与动画锚点

父级配置 JSON **仅在装饰物包装的“缩小空模型”模式生效**；其他模式隐藏该输入，后端也忽略父级配置。模型和材质文件无需添加父级字段。不提供配置或选择“不使用”时，继续使用原来的自动打包逻辑。提供空字典 `{}` 时，所有元件进入统一的默认父级组。

父级名称映射到子元件列表和参数，例如 `parents.json`：

```json
{
  "左门": {
    "children": ["门板", "把手"],
    "anchor": [0, 0.5, 0.5]
  },
  "门框": {
    "children": ["框体"],
    "anchor": [0.5, 0.5, 0.5]
  }
}
```

| 字段 | 用法 |
| --- | --- |
| 父级名称 | 配置表的键，也是导出父实体的名称。 |
| `children` | 必填的非空列表。名称字典引用字典键；物体列表引用唯一 `name`；components 场景引用字符串 `id`。 |
| `anchor` | 可选的 `[x,y,z]`，每轴为 0–1 的有限数。从该父级所有子元件的包围盒最小角向最大角取相对位置，默认 `[0.5,0.5,0.5]`。使用 Y-UP，Y 值决定上下位置。 |

配置仅支持 `children` 和 `anchor`。所有父实体的旋转强制设为 `[0,0,0]`，三轴缩放均使用页面“父实体缩放”的值，即 `[s,s,s]`；不在配置 JSON 中提供 `rotation` / `rotate` 或 `scale` / `scal`。

`[0,0.5,0.5]` 是 X 最小面中心，可用作左侧门轴；`[1,0.5,0.5]` 是 X 最大面中心；`[0.5,0.5,0.5]` 是包围盒中心。
包围盒按完成整体旋转后的世界坐标计算，并包含子元件各自的旋转。修改父级锚点或页面“父实体缩放”会重算子装饰物的局部变换，保持其初始世界位置和形状。子元件自身的旋转仍保留在模型 JSON 中。

快速使用：

1. 上传模型 JSON，选择 **装饰物包装 → 缩小空模型**。
2. 在 **父级配置 JSON（可选）** 中选择上传文件或直接粘贴，填入配置表。页面提供与模型示例配套的父级配置示例下载。
3. 门板与把手放进同一个 `children` 列表，将 `anchor` 设为门轴所在侧。用于动画的父实体保留非静态设置。
4. 点击 **生成 GIA**。查看转换摘要中的父实体名称、`parent_group`、锚点及装饰物归属，再下载并导入编辑器验证动画。

每组上限沿用页面“每组最大物体数”，最高为 999。同一配置组超过上限时，生成 `左门_001`、`左门_002` 等多个父实体；这些父实体共享**整组**计算的位置、旋转和缩放，最后不足上限的一组也不会重新居中。动画时应对这些父实体应用相同变换。

未在表中列出的元件统一进入“默认父级”，原点位于这些元件的共同包围盒中心。默认组超过上限时生成“默认父级_001”“默认父级_002”等父实体，所有拆分父级共享整组中心、零旋转和相同缩放，不会按批次重新居中；默认名称与显式组冲突时自动添加后缀。不存在的子元件、重复分配、歧义名称、非法参数或显式组拆分后的名称冲突会明确报错。具体碰撞与动画效果仍需游戏内验证。

## 转换选项

- 保留普通实体、装饰物包装两条输出路径。
- 整体绕 X 轴旋转以完整模型的包围盒中心为轴心。
- 页面保留共面重叠优化选项，但因计算过慢暂不可开启；转换任务固定关闭该优化。
- 包装模式支持 `BOUNDING_BOX`、`SHRINK_HIDE`、`RANDOM_GROUP_OBJECT`。随机模式每组选择一件物体成为父实体，其余作为装饰物，随机种子可复现结果。
- 普通实体的超范围运行/显示未指定时保留模板设置；显式物体属性覆盖全局默认。
- 碰撞与攀爬写入导出数据，实际编辑器内效果仍需导入验证。
- 缩小空模型模式下，独立父级配置可按名称分组并设置包围盒锚点；未指定的元件统一进入默认组，父级旋转固定为零、缩放统一使用页面值，超限分组共享同一父变换。

## 架构与复用

依赖方向：`UI.page_gpt2gia → miliastra_core.gpt2gia → miliastra_core.export → protobuf`。
UI 使用现有 `run_heavy_action`，兼容本地同步和 RQ Worker；任务只传递数据、不可变设置与进度回调。
核心不依赖 Streamlit，不修改全局 CONFIG；每次转换使用独立临时目录。

- `model.py`：输入解包、材质合并、参数校验与工作流。
- `parents.py`：独立父级配置校验、子元件引用解析、锚点计算与保持共同变换的分组拆分。
- `normalization.py` / `geometry.py`：复用 GPT2Gia 原导出器的归一化、旋转与重叠处理算法。
- `assembly.py`：保留原家具组装核心接口；页面入口已关闭。
- `export.builder`：复用普通实体导出，增加可选模板负载设置保留功能，原调用默认不变。
- `export.decoration`：在既有包装器中合入三种包装模式，保留原透明度和独立实体支持，默认仍为包围盒模式。
- `Template/GPT2Gia_entities.gia` 与 `GPT2Gia_decorations.gia`：源项目使用的两份模板，随目标项目部署，不依赖源项目目录。

复用项目现有 NumPy、SciPy、Protobuf、Streamlit 和任务队列；增加原共面冲突算法需要的 Shapely 2.1.2。

## 验证命令

在项目根目录，使用 `Star.bat` 对应的 Python 运行：

```powershell
python -m unittest discover -s tests -p "test_gpt2gia*.py" -v
python -m compileall -q miliastra_core UI
```

验证覆盖真实模板输出、二进制解析、三种包装模式、分组边界、配色、旋转、非法输入、并发隔离、任务序列化和 Streamlit 页面流程。
父级配置回归测试还覆盖实际 GIA 名称与归属链接、三种模型格式、锚点边界、显式组与默认组超过 999 个子元件时的共同变换、父级零旋转与页面缩放，以及模型整体旋转后所有子元件包围盒角点的世界位置。
文件结构验证不等同于游戏导入验证；自动化测试不连接真实 Redis Worker。
